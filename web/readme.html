Checkout Workbench 工作原理

这个本地页面整合了 checkout 链接生成、Chrome CDP 会话提取、支付页目标锁定、GoPay/Midtrans 辅助流程、页面监控和 browser-use Playwright 自动化。前端负责收集输入与展示状态，真实协议编排和浏览器调试操作由本地 Go 后端与 browser-use 服务完成。

返回控制台

整体结构

浏览器前端

提供三栏工作台，调用本地 Go API 生成 checkout 链接、打开无痕窗口、获取 Session、自动填地址、执行 GoPay 辅助动作，并可调用 browser-use 服务进行网页分析。

本地 Go 后端

提供 checkout、Chrome CDP、Session、GoPay、Midtrans、监控和审计接口，固定监听 127.0.0.1:18473。

browser-use 服务

独立 Node/Playwright 服务，默认监听 127.0.0.1:38765，提供 GET /health 与 POST /run。

核心流程

1

获取会话

用户可粘贴 access token、JWT 或整份 /api/auth/session JSON。也可以打开 Chrome 无痕窗口后调用 POST /api/session/fetch，由后端通过 CDP 在 chatgpt.com 页面中读取 Session JSON。

2

生成 checkout 链接

前端调用 POST /api/checkout 或兼容入口 POST /api/checkout/start。后端校验请求、转发 checkout 上游、初始化 Stripe 页面，并返回 checkout_url、url 和 checkout_session_id。

3

打开并锁定支付页

前端通过 POST /api/incognito/open 打开 checkout 链接，并记录最近打开的 URL。后续 POST /api/checkout/resolve-target 与 POST /api/checkout/auto-fill 都会基于该 URL 校验当前 CDP 目标，避免填错页面。

4

GoPay 与 Midtrans 辅助

GoPay 相关能力由 /api/gopay/full-link、/api/gopay/auto-link、/api/gopay/smart-link、/api/gopay/cdp-otp、/api/gopay/midtrans-linking-fill 等当前已注册接口提供。

5

页面监控与 browser-use

POST /api/gopay/monitor 和 POST /api/pricing/monitor 负责 CDP 监控；browser-use POST /run 负责 Playwright 导航、等待、填表、提交和页面数据提取。

当前本地 Go API

接口 用途 关键输入 关键输出
GET /api/health 健康检查 无 status、time
POST /api/checkout
POST /api/checkout/start		 生成 checkout 长链接 token、plan_name、billing_details、checkout_ui_mode checkout_url、url、checkout_session_id
POST /api/incognito/open 打开 Chrome 无痕窗口 url、new_window ok、url、new_window
POST /api/session/fetch 通过 CDP 获取 Session JSON stream json、diagnostics 或 NDJSON 事件
POST /api/checkout/resolve-target 解析当前 checkout CDP 目标 opened_url current_url、target、candidate_urls
POST /api/checkout/auto-fill 锁定目标并填入随机美国地址 expected_url address、fill_target、filled
POST /api/gopay/full-link 完整 GoPay 链路辅助 access_token、country_code、phone_number、otp_channel、otp、pin ok、stage、stages、summary、payment_voucher
POST /api/gopay/auto-link
POST /api/gopay/smart-link
POST /api/gopay/force-link		 GoPay linking 创建、复用与自动验证 account_id、country_code、phone_number、otp_channel、otp、pin ok、stage、reference_id、summary
POST /api/gopay/cdp-otp
POST /api/gopay/midtrans-linking-fill
POST /api/gopay/snap-probe		 浏览器页面内 OTP、手机号和 Midtrans/Snap 探测辅助 otp、target_url、country_code、phone_number ok、result、browser_result、probe_steps
POST /api/gopay/monitor
POST /api/pricing/monitor		 通过 CDP 采集页面、网络、控制台和资源信息 duration_s、stream、url_filters events、summary、snapshot 或 NDJSON 事件
POST /api/gopay/auto-trigger-check 判断是否满足 GoPay 自动触发条件 source、checkout_url、page_text、submitted ready、reason、conditions

browser-use 服务

GET /health

返回 ok、service: browser-use 和当前端口，用于前端判断 Playwright 自动化服务是否可用。

POST /run

接收 url、browser、headless、waitFor、formData、fieldHints 等字段，执行导航、等待、表单填写、可选提交和页面数据提取。

{
  "url": "https://example.com",
  "task": "browser-use task",
  "browser": "chromium",
  "headless": true,
  "submit": false,
  "waitFor": { "selector": "form" },
  "formData": { "email": "test@example.com" }
}
