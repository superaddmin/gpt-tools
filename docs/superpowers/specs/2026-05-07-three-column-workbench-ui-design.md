# 三栏工作台 UI 优化设计

## 背景

当前页面已经覆盖支付链接生成、无痕窗口、Session 获取、自动填地址、GoPay 绑定、流程监控和 Browser Use 调用等能力。问题不在功能缺失，而在页面呈现更像多个卡片顺序堆叠：首屏层级不够明确，结果 JSON 权重偏高，工具区与主链路混在一起，移动端浮层会遮挡内容。

本次 UI 优化采用「三栏工作台」方向，目标是把页面整理成更专业、更稳定、更适合重复操作的工作界面。

## 设计目标

- 保留当前高效操作路径，不把熟练用户拖进冗长向导。
- 明确三类任务：输入与动作、结果与诊断、辅助工具。
- 提升状态可读性：在线、空闲、运行中、错误、成功要能快速扫到。
- 降低视觉拥挤：统一间距、卡片半径、按钮层级和表单尺寸。
- 保持移动端可用：窄屏下按任务顺序堆叠，二维码浮层不得遮挡关键按钮和结果。
- 避免模态阻塞：继续使用页内提示，不恢复原生 `alert(...)`。

## 页面结构

### 顶部工作台头部

新增轻量 header，展示产品名、当前健康状态和一句任务描述。它不做营销 hero，只作为工作台定位和状态锚点。

内容：
- 标题：`Checkout Workbench`
- 副标题：`生成支付链接、打开无痕窗口、获取 Session，并完成 GoPay 辅助操作。`
- 右侧状态：服务在线、Browser Use 状态或最近操作状态。

### 左栏：主输入与快捷动作

左栏保持为主要操作区：
- Token / Session JSON 输入框。
- 可选 Cookie 和 User-Agent 折叠区。
- 主 CTA：生成支付链接。
- 次级动作：打开无痕窗口、自动填地址、获取 Session JSON。

视觉要求：
- 主 CTA 使用稳定的青绿色实心按钮。
- 次级动作使用轻量边框按钮。
- 三个次级按钮在桌面端一行或两行排列，在移动端保持完整宽度。

### 中栏：结果、步骤流与 JSON

中栏是页面信息重心：
- 顶部放状态摘要：状态、Session、域名。
- 中部放步骤流：识别输入、提取 Token、请求 Checkout、浏览器会话、生成链接。
- 下方放最终结果和支付链接操作。
- JSON 输出默认保留，但视觉上降权，不再挤占首屏过多空间。

视觉要求：
- 步骤流使用更轻的背景和更明显的 active/done/error 状态。
- JSON 区固定最大高度，可滚动。
- 链接按钮与复制按钮对齐，避免长链接撑破布局。

### 右栏：GoPay 与 Browser Use 工具

右栏承载辅助工具：
- GoPay 一键绑定面板默认展开，因为它是当前核心工具。
- Browser Use 面板可以保留在右栏下方，降低视觉权重。
- 流程监控区域保持可展开结果，不抢占主链路首屏。

视觉要求：
- 工具面板和主链路区分明确。
- 表单字段高度一致。
- 监控日志继续保持等宽字体，但减少黑色块的突兀感。

## 视觉系统

### 色彩

- 背景：`#f6f8fb` 或近似浅灰蓝，避免纯白大面积刺眼。
- 面板：白色。
- 主色：青绿色，用于主 CTA、成功、在线。
- 辅助状态：蓝色用于运行中或信息提示。
- 警告：琥珀色。
- 错误：红色。
- 文本：深灰黑，正文使用中性灰，保证 WCAG AA 对比度。

### 字体层级

- 页面标题：24-28px，紧凑但有识别度。
- 面板标题：16-18px。
- 标签：12-13px，字重 700。
- 正文/提示：12-14px，行高 1.5-1.65。
- JSON/日志：等宽字体，12px。

### 间距与圆角

- 页面外边距：桌面 20-28px，移动 10-14px。
- 面板内边距：16px。
- 网格间距：14-16px。
- 卡片圆角：8px，避免过度圆润。
- 输入框高度：40px，按钮高度：42px。

## 响应式策略

- 宽屏 `>=1300px`：三栏布局，左栏 360px，中栏自适应，右栏 340px。
- 中屏 `900px-1299px`：两栏布局，左栏 + 中栏，工具面板自动换到下一行。
- 窄屏 `<900px`：单栏堆叠，顺序为输入、结果、GoPay、Browser Use。
- 手机 `<560px`：按钮组变单列或两列，所有状态摘要变单列。
- 微信群二维码浮层在手机端缩小并靠右下，不遮挡主要按钮；必要时默认折叠。

## 交互规则

- 所有可点击元素需要 `cursor: pointer` 和可见 hover/focus 状态。
- 焦点状态使用明确边框和浅色 ring，键盘用户能识别位置。
- 所有非阻塞反馈继续走页内提示区域，不使用原生 `alert(...)`。
- 长文本、长链接、JSON 输出均不得撑破容器。
- 动画只用于颜色、阴影、边框过渡，尊重 `prefers-reduced-motion`。

## 实施范围

主要修改：
- `web/index.html`：增加工作台头部，调整面板语义结构，必要时给工具区域加 wrapper。
- `web/styles.css`：重做布局、色彩变量、卡片、按钮、表单、状态、响应式。
- `web/app.js`：仅做与样式结构有关的选择器兼容；不改业务流程。

不在本次范围：
- 不改 GoPay / Session / Checkout 的业务 API。
- 不新增依赖。
- 不引入前端框架或构建工具。
- 不修改支付提交流程。

## 验收标准

- 桌面端首屏能同时看到输入、结果、GoPay 三个核心区域。
- 移动端无水平滚动，二维码不遮挡主按钮和结果状态。
- `web/app.js` 中不出现原生 `alert(...)`。
- Session 获取、支付链接生成、自动填地址按钮仍可触发原有 API。
- `go test ./...` 通过。
- 本地服务重启后 `GET http://127.0.0.1:18473/` 返回 200。
