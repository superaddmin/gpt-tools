# UI/UX Pro Max

来源：<https://github.com/nextlevelbuilder/ui-ux-pro-max-skill>
版本参考：2.5.0
许可证：MIT

## 使用场景

当任务涉及以下内容时使用本技能：

- 页面布局结构分析与修复
- 响应式适配检查
- 元素间距、对齐、视觉错位排查
- 表单、按钮、卡片、导航、工具区、结果区等 UI 组件体验优化
- 可访问性、键盘导航、焦点状态与触控目标检查
- 不改变业务逻辑前提下的界面质量提升

## 当前项目执行原则

本项目是本地 Checkout Workbench，核心页面位于 `web/index.html`、样式位于 `web/styles.css`、业务脚本位于 `web/app.js`。

执行 UI/UX 修复时必须遵守：

1. 优先使用 CSS 修复布局、对齐、间距和响应式问题。
2. 不修改 GoPay、Checkout、Session、Browser Use 的接口调用和数据处理逻辑。
3. 不随意改变已有 DOM id，尤其是被 `web/app.js` 或内联脚本查询的节点。
4. 不进行无关视觉重设计，除非用户明确要求。
5. 保持桌面、中屏、移动端都有可读、可操作、无横向滚动的布局。
6. 修改后运行 HTML/CSS 诊断和 Go 测试。

## 布局审查清单

### 1. 响应式布局

- 视口宽度 375px、768px、1024px、1440px 下无水平滚动。
- 三栏布局在中屏能稳定降级为两栏/单栏。
- 工具区、结果区、表单区在窄屏下按主流程顺序展示。
- 文本、按钮和输入框不会溢出容器。

### 2. 对齐与间距

- 同一面板内标题、内容、按钮、状态区使用一致间距节奏。
- 卡片之间保持稳定 gap，不出现局部过密或过空。
- 中间结果栏高度应尽量与左侧输入栏平衡。
- 步骤流可横向并排时不应纵向占用过多空间。

### 3. 交互与可用性

- 所有按钮和链接有可见焦点状态。
- 主要操作按钮保持清晰，次要操作视觉权重更低。
- 高级选项使用渐进披露，不阻塞主流程。
- 调试 JSON 默认可折叠，避免压缩核心结果内容。

### 4. 可访问性

- 页面保留 `viewport` 元信息且不禁用缩放。
- 表单字段有可见 label。
- 链接、按钮、summary 元素具有键盘可聚焦状态。
- 错误信息不只依赖颜色表达。

### 5. 验证步骤

1. 检查 HTML/CSS 诊断。
2. 运行 `go test ./...`。
3. 启动本地 Go 服务后，使用浏览器验证：
   - 1440×900 桌面视口
   - 1024×768 平板/中屏视口
   - 768×900 窄屏视口
   - 390×844 手机视口
4. 截图观察是否存在错位、溢出、异常空白或遮挡。
5. 确认核心工作流按钮仍可见且顺序合理。

## 修复优先级

1. 先修复会破坏使用的问题：水平滚动、遮挡、字段不可见、按钮错位。
2. 再修复布局效率问题：中间栏过高、步骤流过长、结果区信息过密。
3. 再修复一致性问题：间距不统一、卡片高度不平衡、断点规则不一致。
4. 最后处理轻微视觉问题：非必要颜色、阴影、动效调整需用户明确同意。
